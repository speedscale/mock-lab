# Mock a dependency needed at startup

This lab starts a Go service that calls a local configuration backend before it listens for requests. The committed RRPair records `GET /bootstrap/config?environment=lab&requestId=sample-001`. The service's current startup request sends only `environment=lab`. With passthrough disabled, the recorded signature misses that request and startup fails with a 404.

The [blueprint](proxymock/blueprints/ignore-request-id.json) removes `http:queryparams:requestId` from the mock signature for `/bootstrap/config`. It keeps the host, method, path, and `environment` as match conditions. Every name and request in this lab is synthetic.

## Run the proof

Install and initialize `proxymock`, then run this from `labs/startup-mock`. You need Go 1.23 or newer, `curl`, and free ports 4140 and 18080.

```shell
make verify
```

The script first runs the service against a copy of the recording without the blueprint. Startup fails with a 404. It then runs against the recording with the blueprint, while the backend is stopped. A `ready` response from `/healthz` confirms that proxymock served the startup dependency. Both runs use `--no-passthrough`. Logs are in `.run/`.

## Recreate the recording

The backend exists only to generate the fixture. Start it in one terminal:

```shell
make build
./bin/config-backend
```

In another terminal, run proxymock from this lab directory. Stop the recording after the startup request appears:

```shell
STARTUP_QUERY='environment=lab&requestId=sample-001' proxymock record --out ./proxymock/recording -- ./bin/config-service
```

Stop the backend before running `make verify`. The [RRPair](proxymock/recording/localhost/2026-09-29_19-28-04.881731Z.md) contains only traffic generated by these two local programs.
